## 2026-09-09 · (해시 미정) · fix: parse K-apt facility strings by category

**영역**: 매매 › 단지 상세 › 주변 시설
**사용자 관점 변경**: 교육·편의 시설이 칩 나열이 아니라 **분류 | 이름** 행으로 보인다 (`초등학교 | 구암, 신봉, 은천초등학교`). `공원()` 같은 빈 항목과 전화번호가 사라진다. 단지 내 시설은 그대로 칩이고 `기타`는 뺀다.
**데이터·API**: API 변경 없음. K-apt 원문 파싱 규칙만 변경 —
- `convenient_facility` / `education_facility`: `분류(내용) 분류(내용) …`. **괄호 깊이를 세며 최상위 공백에서만** 끊는다(괄호 안에 공백·쉼표·전화번호·중첩 괄호가 온다). 괄호 안 쉼표(`,`/`，`/`/`)는 같은 분류의 여러 이름. 전화번호(`031-5189-4951`, `1522-2500`, 감싼 괄호 포함)는 삭제. 빈 괄호면 항목 삭제. 같은 분류는 하나로 합침.
- `welfare_facility`: 쉼표 분리, `기타` 삭제.
- 도메인: `Surroundings.convenient/education: List<FacilityGroup(category, names)>`, `welfare: List<String>`.
**네비게이션**: 없음
**문구**: 없음
**규칙·엣지케이스**: 닫는 괄호가 없어도 마지막 조각은 살린다. 분류만 있고 괄호가 없으면 버린다. 실측 샘플은 `FacilityParserTest` 참고.
**iOS 체크리스트**:
- [ ] 시설 파서를 위 규칙으로 교체 (테스트 7개 케이스 그대로 옮기면 됨)
- [ ] 단지 상세 주변 시설: 교육·편의는 행(분류/이름), 단지 내는 칩

# iOS 동기화 변경 기록

이 폴더는 **Android(이 레포)에서 바뀐 것을 iOS 레포가 따라오기 위한 기록**입니다.
iOS 쪽 작업자(사람이든 Claude든)는 코드 전체를 다시 읽을 필요 없이 `CHANGELOG.md`의
새 항목만 읽으면 됩니다.

## 읽는 법 (iOS 쪽)

1. iOS 레포에 **마지막으로 반영한 Android 커밋 해시**를 적어 둔다 (예: `docs/android-sync.md`에 한 줄).
2. `CHANGELOG.md`는 최신 항목이 위에 있다. 그 해시 **위쪽** 항목만 읽는다.
3. 항목마다 "iOS 체크리스트"가 있다. 그대로 따라 하면 된다.
4. 반영이 끝나면 1의 해시를 갱신한다.

기준선(`## 기준선`) 항목 아래는 이미 iOS에 반영된 상태라 읽지 않아도 된다.

## 쓰는 법 (Android 쪽)

- 동작·데이터 모델·API 계약·네비게이션·문구·DB 스키마가 바뀌는 커밋마다 **항목 하나**를
  `CHANGELOG.md` **맨 위에** 추가하고, **같은 커밋에 포함**한다.
- 순수 리팩터·빌드 설정·테스트만 바뀐 커밋은 제목 한 줄 + `iOS 영향 없음`으로 적는다.
- 커밋 해시는 커밋 후에야 알 수 있으므로 항목에는 **커밋 제목**을 적는다. 해시가 필요하면
  `git log --oneline --grep="<제목>"`으로 찾는다. 다음 항목을 쓸 때 앞 항목의 해시를 채워 넣어도 된다.
- 기록 없이 올라간 커밋을 발견하면, 다음 기록 때 그 커밋들도 항목으로 보충한다.

## 항목 형식

```markdown
## YYYY-MM-DD · <커밋 해시 또는 (해시 미정)> · <커밋 제목>

**영역**: 어느 탭/화면인지
**사용자 관점 변경**: 무엇이 어떻게 보이고 동작하나 (기획 의도 한 줄 포함)
**데이터·API**: 엔드포인트/파라미터/응답 필드, 도메인 모델 필드, DB 테이블·버전
**네비게이션**: 새 목적지, 인자, 진입점
**문구**: 신규/변경 문자열 — `key` → 한국어 원문 (iOS가 그대로 쓰도록)
**규칙·엣지케이스**: 빈 상태, 상한, 정렬, 예외 처리
**iOS 체크리스트**:
- [ ] …
```

문구는 Android `app/src/main/res/values/strings.xml`의 key를 그대로 적는다. iOS는 key를 바꿔도
되지만 **한국어 원문은 같아야** 한다.
